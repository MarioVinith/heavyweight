# HEAVYWEIGHT — Personal Weights Tracker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A private, installable PWA where the user logs gym sessions (exercise → sets of weight×reps) and watches a graph prove they're lifting heavier, synced between phone and laptop.

**Architecture:** Vite + React SPA talking directly to Supabase (Postgres + magic-link auth, row-level security locks all rows to the owner). All user data fits trivially in memory, so the app loads everything once into a React context store, computes stats client-side, and mirrors data to localStorage for offline reading. Deployed as a static site on Netlify via GitHub auto-deploy.

**Tech Stack:** Vite, React 18, TypeScript, react-router-dom, @supabase/supabase-js v2, Recharts, vite-plugin-pwa, Vitest, @fontsource/anton + @fontsource/oswald.

## Global Constraints

- Units are **kg** everywhere. Weight inputs accept decimals (e.g. 7.5).
- Exercise names are **canonical**: picked from the user's library; creating a new one adds it to the library. No free-text duplicates ("Bench" vs "Bench Press") possible in normal flows.
- A day's log is **fully editable** after applying a template (add/remove/swap exercises, add/remove sets) without changing the template.
- Set count per exercise is **flexible** (screenshots show 2 or 3); templates carry `target_sets` and `target_reps` per exercise.
- Progress headline metric = **top-set weight**; one-tap toggle to **total volume** (Σ weight×reps).
- v1 features: last-time hint, PR detection ("NEW PR" toast + PR list). Deliberately out: rest timer, CSV export, body-weight, RPE, superset timing logic (labels like A1/B2 are kept as ordering tags only).
- Look: Rocky boxing-gym — dark/gritty, gold `#e8b93b` + blood-red `#b3202a`, heavy condensed display type (Anton), Oswald for labels/numbers. App name: **HEAVYWEIGHT**.
- $0 to run: Supabase free tier + Netlify free tier. No paid services.
- Secrets: `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` live in `.env.local` (gitignored) and Netlify env vars. The anon key is public-by-design; RLS is the real gate.
- If env vars are missing, the app renders a friendly "backend not configured" notice (lets us build/preview before Supabase exists).

## Data Model (3 tables, all RLS: `user_id = auth.uid()`)

```
exercises: id uuid pk, user_id, name text  — unique (user_id, name)
templates: id uuid pk, user_id, name text, items jsonb
           items = [{ exercise_id, label, target_sets, target_reps }]
workouts:  id uuid pk, user_id, workout_date date, entries jsonb — unique (user_id, workout_date)
           entries = [{ exercise_id, label?, target_reps?, sets: [{ weight, reps }] }]
```

Rationale: single-row upsert per day = atomic saves, trivial sync, no join complexity. A year of training ≈ 150–300 rows total. Personal scale forever.

**Interfaces produced (later tasks consume exactly these):**

```ts
// dates.ts — all dates are 'YYYY-MM-DD' strings, local time
todayISO(): string
addMonths(ym: {y:number,m:number}, delta: number): {y:number,m:number}
monthGrid(y: number, m: number): (string|null)[]  // 42 cells, Mon-first, null = pad
formatDay(iso: string): string                    // "Thu 17 Jul"

// stats.ts
type SetEntry = { weight: number; reps: number }
type WorkoutEntry = { exercise_id: string; label?: string; target_reps?: string; sets: SetEntry[] }
type Workout = { id?: string; workout_date: string; entries: WorkoutEntry[] }
topSetWeight(sets: SetEntry[]): number            // max weight over sets with weight>0, else 0
totalVolume(sets: SetEntry[]): number             // Σ weight*reps
exerciseHistory(ws: Workout[], exId: string): { date: string; top: number; volume: number }[] // date-asc, skips empty
lastEntryFor(ws: Workout[], exId: string, beforeDate: string): { date: string; sets: SetEntry[] } | null
prState(ws: Workout[], exId: string, date: string): { topPR: boolean; volumePR: boolean } // strictly beats all earlier dates

// seed.ts
SEED_EXERCISES: string[]                          // the 8 canonical names
SEED_TEMPLATE: { name: string; items: { exercise_name: string; label: string; target_sets: number; target_reps: string }[] }
```
